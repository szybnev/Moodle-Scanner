# AGENTS.md

Non-destructive external Moodle scanner (`moodle_scanner` package, CLI `moodle-scanner` / `python scanner.py`).

## Invariants

- **Read-only scanning.** Target requests are `GET`/`HEAD` through `HttpClient` only, same-origin redirects only. New checks observe public responses; they never log in, submit forms, create accounts or guess credentials. There is no exploit mode; proposals for one are out of scope.
- **Permissive deps and sources only.** Runtime and dev dependencies must be MIT, BSD, Apache-2.0, ISC, PSF or similar; GPL, AGPL, LGPL, SSPL, PolyForm and Commons Clause are excluded. Code or data from badmoodle and droopescan is excluded; MIT code may be reused only with its notice. Record every new dependency or data source in `THIRD_PARTY_NOTICES.md`.
- **Facts-only data.** `moodle_scanner/data/*.json` holds tag names, URL paths, git blob ids, advisory ids/CVEs/severities/version lists/URLs, plugin components and versions. Moodle source, advisory prose and plugin code stay out of the repo, including test fixtures (hand-write minimal bodies; see `tests/support.py`).
- **Secrets stay unreported.** Evidence for exposed config files names settings, never values.
- **Lab stays local.** Lab containers bind to `127.0.0.1`; scanning targets are local lab instances only.

## Layout

- `moodle_scanner/versions.py` version parsing/order; `advisories.py` range parsing + matching; `fingerprints.py` adaptive detection; `checks.py` misconfiguration checks; `plugins.py` enumeration; `scan.py` pipeline, report, exit codes; `cli.py` argparse/text output; `httpclient.py` transport.
- `moodle_scanner/update/` data builders (git tag mirror, moodle.org scraper, plugins API). `moodle_scanner/schema/scan-result.schema.json` is the report contract.
- `tests/` offline pytest; `tests/support.py` local replay server + synthetic data; `tests/fixtures/*.json` recorded status/header shapes.
- `lab/` Docker harness; `lab/results/` committed evidence; `docs/validation-matrix.md` generated by `lab/lab.py matrix`.

## Commands

```sh
uv sync
uv run pytest
uv run ruff check . && uv run ruff format --check .
uv run moodle-scanner --update --vuln --update-plugins   # refresh data (network: GitHub, moodle.org)
```

Dependencies change only through `uv add`/`uv remove` with exact pins; commit `uv.lock`.

## Workflow

- Behaviour changes ship with a test at the CLI/report seam (`tests/test_scan_cli.py`) or the module's public function; tests stay offline and deterministic (local replay server, `tmp_path`, injected clock).
- Report shape changes: update the schema, bump `schema_version` (minor for additive), update the README JSON table.
- Detection, check or plugin logic changes: run the lab (`docs/lab.md`), regenerate the matrix, commit `lab/results/` and `docs/validation-matrix.md`.
- Data refresh: commit regenerated `moodle_scanner/data/` separately with the command used in the message.
- User-visible changes: add a `CHANGELOG.md` entry.

## Read when

- `README.md` — CLI options, JSON fields, exit codes, limitations (user-facing contract).
- `docs/lab.md` — before touching `lab/` or validating detection changes.
- `THIRD_PARTY_NOTICES.md` — before adding a dependency or data source.
